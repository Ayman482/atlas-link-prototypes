## 1. حالة البيانات وعزل الحسابات — `apps/option-c/src/lib/store.tsx`

**D1 — `useQ`**
- الحالة صارت مربوطة بـ«نطاق» = الحساب + اسم الاستعلام + المعاملات (`queryScope`).
- العرض يُشتق متزامناً (`viewOf`)، فلا تُعاد بيانات نطاق آخر ولا لعملية عرض واحدة:
  - استعلام معطّل ← `{ data: null, loading: false }`.
  - نطاق جديد ← `{ data: null, loading: true }`.
- الاستجابات المتأخرة من نطاق قديم تُتجاهل.
- التحديث داخل النطاق نفسه يُبقي البيانات ويضيف `refreshing`، فلا وميض هياكل التحميل.

**D2 — ملف المستخدم `me`**
- يُمسح عند تغيّر الحساب.
- السياق لا يعرض `me` إلا إذا طابق `me.user.id` الحساب النشط.

**D3 — الخروج عند الخطأ**
- إعادة جلب `me` تُخرج المستخدم فقط عند 401/`UNAUTHENTICATED`، مع استدعاء `logout()`.
- انقطاع الشبكة المؤقت لا يُنهي الجلسة.

## 4. التتبع والقياس

### T2 — تفاصيل الشحنة (`admin/ops.tsx`، مشتركة بين الإدارة والبوابة)
- **آخر موقع مؤكد**: الوقت، والعمر النسبي، والمصدر، وشارة «محاكاة»، وحالة حداثة صحيحة:
  - أثناء الطيران ← «مستنتج».
  - قراءة حية مع موقع غير حي ← «متأخر».
- **آخر قراءة**: وقت الجهاز ووقت الاستلام منفصلان، وشارة «قراءة مخزنة» عند الاقتضاء، وصف «عرض الحرارة: حالية / آخر قيمة معروفة فقط».

### T1 — تتبع جوال العميل (`mobile/CustomerMobile.tsx`)
- تنبيه «لا يتوفر موقع مباشر أثناء الرحلة الجوية» بدور `status`.
- الحالة «في رحلة جوية».
- الحرارة عبر `f.temp`، وعمر الموقع ومصدره.

### T3 — Flutter `track.dart`
- الشارة تعكس حداثة **الموقع**: «مباشر» فقط إن كان `isLive`.
- الحالة من `operationalStatus`، و«ليس موقعاً مباشراً» عند الاقتضاء.

### T4 — صفحة الجهاز
- النطاق المرصود يُمرَّر كـ`observedOnly`.
- `TempChart` لا يرسم حزمة أو خطوط حدود ويكتب: «لا يوجد ملف حراري مرتبط بالجهاز الآن — لا تُعرض حدود مسموحة».
- كل القيم تُنسّق بخانة عشرية واحدة.

### T5 — نص المعاينة (`mobile/kit.tsx`)
- «معاينة متصفح للمراجعة التصميمية… بيانات العرض (ليست بيانات حقيقية)».
- المسار داخل `<code dir="ltr">`.

### T6 — Flutter `format.dart` و`temp_chart.dart` و`temperature.dart`
- «°م» بالعربية و«°C» بالإنجليزية.
- حدود منسّقة.
