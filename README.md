# أطلس لينك للشحن الطبي — النماذج الأولية التفاعلية

مستودع واحد يضم الأساس المشترك (المرحلة 1) الذي تُبنى فوقه خيارات التصميم الثلاثة A وB وC، ومشروعا Flutter.

> **تنبيه:** كل البيانات وهمية ومُعلَّمة «بيانات عرض». القراءات الحرارية ومواقع GPS ليست من أجهزة حقيقية. الدفع، ZATCA، الرسائل النصية والبريد، أحداث الناقلين، وأوامر الأجهزة كلها **محاكاة**.

## المتطلبات

- Node.js 22.13 أو أحدث، npm 10
- (للمرحلة 5) Flutter 3.24+ مع Android Studio أو Xcode

## التشغيل

```bash
npm install
npm test            # 32 اختبار قبول (UAT-001..015، DB-AT، السيناريوهات، تكامل API)
npm run api         # خادم API على http://localhost:4000/api/v1 بقاعدة بيانات دائمة في data/demo-db.json
npm run api:reset   # إعادة توليد بيانات العرض
```

معاينة الأساس المشترك محلياً:

```bash
cd apps/foundation-console && node build.mjs   # يُنتج dist/index.html
```

### كيف تبقى الواجهات متسقة

كل تطبيق (الإدارة، البوابة، العميل، المندوب، وفي الخيارات الثلاثة) يستدعي **نفس الأوامر** عبر `@medlog/client`:

- **محلياً / للتطوير:** `NEXT_PUBLIC_MEDLOG_API=http://localhost:4000/api/v1` ← كل التطبيقات تكتب في قاعدة بيانات الخادم الدائمة، وتصلها التحديثات لحظياً عبر SSE. تغيير في تطبيق المندوب يظهر فوراً في برج التحكم وبوابة العميل.
- **المعاينات المستضافة:** لا يمكن تشغيل خادم داخل صفحة مستضافة، فيعمل المحرك نفسه داخل المتصفح ويحفظ في التخزين المحلي، وتتزامن التبويبات المفتوحة (الإدارة في تبويب والمندوب في آخر) عبر BroadcastChannel.
- **Flutter:** يتصل بنفس خادم API (`http://10.0.2.2:4000` من محاكي Android).

### المحرك

- كل أمر معاملة ذرّية: تغييرات المجال + سجل التدقيق + حدث outbox، أو لا شيء (تراجع كامل عند الخطأ).
- الصلاحيات تُفرض في المحرك وليس في الواجهة: النطاق حسب الدور والمؤسسة والفرع، و404 بدل 403 لعدم كشف وجود سجلات عميل آخر.
- المبالغ بالهللة (أعداد صحيحة)، والقيود المرحّلة غير قابلة للتعديل، والتصحيح بقيد عكسي.
- الانتقالات المحروسة لحالة الشحنة (SHP-004)، وفصل الحالة اللوجستية عن اتصال الجهاز وعن القرار السريري (BR-006).

## التكاملات المحاكاة (لا اتصال حقيقي)

| التكامل | السلوك في النموذج | المرجع |
| --- | --- | --- |
| بوابة الدفع | نجاح/فشل محاكى، رقم مرجعي `SIM-…` | OD-006 |
| ZATCA | حالة `simulated_cleared` للعرض فقط | FIN-006 |
| SMS / بريد / Push | تُسجَّل كـ `simulated_sent` ولا تُرسل | INT-001 |
| أحداث الناقل الجوي | مولّدة أو تُطلق يدوياً | OD-007 |
| بوابة GPT45-M | قراءات حقن تجريبية، عزل IMEI غير مسجّل، dead-letter، إعادة تشغيل | VAL-01..09 |
| أوامر الأجهزة | ACK محاكى بعد الاعتماد | IOT-DIR |
| الخرائط | خريطة متجهية داخلية بلا مزود خارجي | — |
| HL7/FHIR | مرحلة لاحقة | INT-003 |
| النسخ والاستعادة | سجلات تشغيل محاكاة | SEC-004 |

## قيود معروفة

- تحليل بروتوكول GPT45-M الفعلي، اختبارات الحمل، والبنية السحابية خارج نطاق النموذج الأولي (موثقة كتنفيذ خارج الواجهة).
- قيم الملفات الحرارية تجريبية وغير معتمدة (OD-011).
- رمز الدخول في خادم العرض موقّع بمفتاح ثابت للعرض فقط.
